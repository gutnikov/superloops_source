# Loops

A coding agent becomes autonomous when every action it takes has a check that the agent runs itself and that
returns an unambiguous, machine-readable signal: an exit code, `file:line:message`, JSON, a screenshot, or the
answer to a log query. Almost every quality attribute (the "-ilities") can be turned into such a sensor, not just
testability and observability. This approach is now called harness engineering.

This catalog has one folder per loop, `<id>/card.md`: a pattern the harness engineer turns into a concrete loop in a
project. It has 103 loops. 71 come from the research "Feedback loops for an autonomous coding agent: a catalog by
quality attributes" (unpublished, in Russian; it says 70 cycles but lists 71). Nine were added here:
[review of document texts](document-review/card.md), built on the `text-quality` part;
[the spec check](spec-check/card.md), built on the `spec` part;
[the acceptance loop](acceptance-loop/card.md), a composite loop from requirements to green acceptance tests;
[the calibration of a loop's agent](agent-calibration/card.md); and five that the super-loops need:
[triage](triage/card.md), [the reproduction gate](reproduction-gate/card.md),
[behaviour invariance](behaviour-invariance/card.md), [release confirmation](release-confirmation/card.md)
and [the discovery decision](discovery-decision/card.md). The other 16 come from a note on human-in-the-loop loops.
With two loops of the research, [the audit trail](agent-audit-trail/card.md) and [user feedback](user-feedback/card.md),
18 loops have a person as the sensor: the [human-in-the-loop loops](human-in-the-loop.md). Seven come from the code
of the open-source coding agent [pi](https://github.com/earendil-works/pi): [guide lift eval](guide-lift-eval/card.md),
[docs audit](docs-audit/card.md), [tool-use telemetry](tool-use-telemetry/card.md),
[tests against a scripted model](scripted-model-tests/card.md), [terminal UI through tmux](terminal-ui-tmux/card.md),
[simplification pass](simplification-pass/card.md) and [changelog audit](changelog-audit/card.md).

What a card holds, and how to add one: [FORMAT.md](FORMAT.md). [index.yaml](index.yaml) lists every loop with its
summary and its fields, so a tool or an agent can choose loops without opening each card; it and the list below are
generated by `python3 ../scripts/catalog.py index`.

Every loop has a place in a project's [super-loops](../super-loops/README.md) (delivery, remediation, maintenance
and discovery): a super-loop and one of its phases, such as `delivery/gate`. The `places` field of a card lists them,
`index.yaml` lists the loops of every place under `by_place`, and the Phases table of each super-loop names the
same loops. The `stages` field says something else: where the loop runs, such as `ci` or `production`.

## Terms

From Birgitta Böckeler (Thoughtworks), "Harness engineering for coding agent users":

- **Guides** act before the agent acts: AGENTS.md, skills, LSP.
- **Sensors** give feedback after it acts: tests, linters, logs, the browser, reviewer agents. Every loop in
  this catalog is a sensor.
- Both are either **computational** (deterministic, seconds) or **inferential** (LLM-as-judge: more expensive and
  non-deterministic).
- With sensors only, the agent repeats the same mistakes. With guides only, it never learns whether the rules
  worked.

Behaviour is the hardest to check: tests the agent wrote itself are not enough. Independent behaviour checks are
the most valuable: [mutation testing](mutation-testing/card.md),
[property-based tests](property-based-tests/card.md), [approved fixtures](approved-fixtures/card.md),
[e2e](e2e-browser/card.md), a separate [verification agent](verification-subagent/card.md).

## What makes a loop fit for an agent

1. **One known command.** It is written in CLAUDE.md or AGENTS.md, or described in `--help`. A CLI costs less
   context than a GUI.
2. **Speed fits its place in the process.** Seconds for every edit, minutes in CI, hours on a schedule. "Keep
   quality left" (Böckeler).
3. **Determinism.** A flaky sensor teaches the agent to ignore the signal.
4. **Machine-readable, compact output.** An exit code, `file:line:message`, JSON or SARIF.
5. **A fix instruction in the error message.** Where a rule had none, Böckeler saw the agent raise the
   complexity threshold instead.
6. **Protection from bypass.** The agent may disable or delete tests (Kent Beck: "any indication that the genie
   was cheating"). Sensors the agent can edit need protection; the final ones must be out of its reach: CI,
   mutations, production.
7. **Isolation.** A sandbox lets the agent run without confirming each action.
8. **Enforced by hooks, not by the prompt.** CLAUDE.md is advice; hooks are deterministic.

## Where to start

The order below is for a project that has none of these loops. Do not build every step: choose by the project's
profile and the failures it has ([../profile.md](../profile.md)).

1. **`verify` in one command**: [build](build/card.md), [types](type-check/card.md),
   [lint](lint-with-fix-instructions/card.md) and [unit tests](red-green-tdd/card.md), plus the
   [formatting hook](autoformat-hook/card.md) and the [Stop hook](stop-hook/card.md). Boris Cherny: "give
   Claude a way to verify its work. If Claude has that feedback loop, it will 2-3x the quality of the final
   result".
2. **Behaviour**: [red/green TDD](red-green-tdd/card.md) with protected tests,
   [mutations on the diff](mutation-testing/card.md), [property-based tests](property-based-tests/card.md).
   When requirements come as tickets or texts: the [acceptance loop](acceptance-loop/card.md), which makes them
   the oracle.
3. **The agent sees the app**: [an app per worktree](isolated-environment/card.md),
   [Playwright](e2e-browser/card.md) with [screenshots](visual-screenshot-check/card.md),
   [axe](accessibility-checks/card.md), `init.sh`.
4. **Observability in dev**: [structured logs](structured-logs/card.md),
   [OTel](traces-opentelemetry/card.md), an ephemeral telemetry stack,
   [performance budgets](perf-budgets-telemetry/card.md).
5. **CI gates**: [fitness functions](architecture-fitness-functions/card.md), [Semgrep](sast/card.md),
   [GitLeaks](secret-scanning/card.md), [SCA](dependency-scanning-sbom/card.md) and
   [licenses](license-check/card.md), [oasdiff or buf](api-breaking-changes/card.md),
   [Squawk or Atlas](db-migration-lint/card.md), [size-limit](bundle-size-budget/card.md) or
   [Lighthouse](lighthouse-ci/card.md), [Pact](contract-tests/card.md). A
   [limited number of CI rounds](ci-clean-infra/card.md).
6. **Production and the inferential layer**: [Sentry MCP](error-tracking/card.md),
   [SLOs](slo-degradation/card.md), [canaries](canary-feature-flags/card.md), and the
   [release confirmation](release-confirmation/card.md) that closes delivery,
   [reviewer agents](agent-code-review/card.md), [garbage collection](garbage-collection/card.md),
   [evals](llm-evals/card.md). A [UX evaluator](ux-evaluator/card.md) only where a single model cannot
   do the job reliably.
7. **Always: the [steering loop](steering-loop/card.md).** Turn every escape and every repeated mistake into code
   (a lint or a test) rather than into text.

## Caveats

- The OpenAI and Stripe numbers are the companies' own reports. OpenAI writes that the result "depends heavily
  on the specific structure and tooling of this repository".
- A harness that checks behaviour is not solved yet. No sensor can check correctness if a person has not
  specified what they want. The [acceptance loop](acceptance-loop/card.md) is this catalog's answer: the person
  specifies once, as an approved spec, and acceptance tests derived from it check every change.
- Too many rules can drive the agent into a "spiral of over-engineered refactorings" (Böckeler).
- Inferential sensors are expensive and non-deterministic; run them selectively, and let one block only after it
  is [calibrated](agent-calibration/card.md).
- Production data is untrusted input. `browser_run_code_unsafe` in Playwright MCP is effectively remote code
  execution.
- The ISO/IEC 25010:2023 sub-characteristics were checked against secondary sources only (the standard is paid).
  Some tools (k6, Trivy, ZAP, cargo-fuzz) reflect common practice and were not checked separately.

### Correctness

_The product does what it was specified to do: functional suitability, completeness, faultlessness._

- [Acceptance loop: from requirements to green acceptance tests](acceptance-loop/card.md): A requirement becomes an approved spec, then acceptance tests that fail; the agent works until they pass. The gate reports, per requirement, whether its tests were red before and green after.
- [Agentic manual testing](agentic-manual-testing/card.md): The agent tries the code by hand with `python -c`, temporary files, `curl` or a browser; each defect it finds becomes a permanent test, written red/green.
- [Behaviour invariance](behaviour-invariance/card.md): Maintenance must change no expected value. The gate fails on a changed expected value, red tests or a measure not improved against the baseline; a changed expected value goes back to triage.
- [Bug → failing test → fix](bug-failing-test-fix/card.md): Red/green for a bug: the agent starts from a test that reproduces the bug and fails, changes the code until it passes, and runs the whole suite.
- [Build / compile](build/card.md): The agent edits code and runs `build`. It reads compiler errors with file and line and fixes them until the command exits with code 0.
- [Calibration of a loop's agent](agent-calibration/card.md): A loop's agent runs at least three times on eval cases with known answers; it may block only once its agreement reaches a threshold a person approved, and every miss becomes a new case.
- [E2E through browser automation](e2e-browser/card.md): The agent starts the dev server and walks a scenario with Playwright or Puppeteer. That is how it finds out that a feature does not work end to end even though the unit tests and `curl` pass.
- [Eval suites for LLM features](llm-evals/card.md): The agent changes a prompt and runs the evals; a drop in the metric counts as a failure.
- [Exploratory testing](exploratory-testing/card.md): The person tries the product by hand and writes a bug report; the agent reproduces the bug with a failing test and fixes it.
- [Guide lift eval](guide-lift-eval/card.md): The agent does the same tasks with and without a guide, each run in a fresh isolated environment; the guide stays only if the paired pass rates show that it helps.
- [LSP diagnostics after every edit](lsp-diagnostics/card.md): Right after every edit the agent gets the language server's diagnostics, before any build.
- [Progress file and feature list](progress-file-feature-list/card.md): Long work over many sessions: a JSON feature list and a progress file carry the state; each session takes one failing feature and marks it passing only after an e2e check.
- [Property-based tests](property-based-tests/card.md): The agent states invariants and writes property tests for them. The framework finds a minimal counterexample, and the agent fixes the code.
- [Release confirmation](release-confirmation/card.md): After a deploy, a job judges a snapshot of a window: the change is confirmed only if production runs it, its signal appeared often enough, and nothing is worse than under the previous version.
- [Reproduction gate](reproduction-gate/card.md): A fix counts only against a reproduction that failed first. The agent fixes until it passes; the gate reports whether it was red before and green after, and whether any other test changed.
- [Sample audit](sample-audit/card.md): On a schedule, the person reviews a random sample of what the agent did or merged without them, and marks where it differs from what they expected.
- [Snapshot / golden / approved fixtures](approved-fixtures/card.md): A test compares the output with a stored reference; the agent fixes an unexpected diff and proposes an expected one to a person as the new reference.
- [Snapshots of what the model sees](prompt-snapshots/card.md): A scripted scenario captures every request the code sends to the model and compares it, as readable text grouped by prompt-cache prefix, with a reviewed snapshot.
- [Spec check](spec-check/card.md): The agent runs `specs.py check` and each layer's check on the changed spec; every gap comes back as a message naming the element and what is missing, before the test writer gets the spec.
- [Stop hook / `/goal`](stop-hook/card.md): When the agent tries to end its turn, a hook runs the check and sends the agent back to work while it fails; `/goal` does the same with a model that judges the transcript.
- [Terminal UI through tmux](terminal-ui-tmux/card.md): The agent runs a terminal app in a tmux session of fixed size, sends keys and reads the screen with capture-pane; a smoke test passes only after a real interaction, not at startup.
- [Tests against a scripted model](scripted-model-tests/card.md): Code around an LLM is tested against a fake provider that replays scripted replies and tool calls: deterministic, in CI, with no network and no tokens.
- [Type checking](type-check/card.md): The agent runs `tsc --noEmit`, `mypy` or `pyright` and fixes the type mismatches it finds.
- [Verification subagent](verification-subagent/card.md): When the working agent says a task is done, a separate subagent with a fresh context tries to prove the claim wrong.

### Alignment

_The work is what the person meant: the intent, the plan and the result match what was wanted._

- [Acceptance criteria and references from a person](human-acceptance-criteria/card.md): The person writes or approves references: acceptance tests, "input → expected output" examples and reference snapshots. From then on the agent works against them without the person.
- [Asynchronous questions with assumptions](async-questions-with-assumptions/card.md): The agent writes down each non-blocking question with the assumption it made and keeps working; at the end of the task the person confirms or cancels each assumption in one batch.
- [Calibrating an LLM judge on an expert (critique shadowing)](llm-judge-calibration/card.md): One expert grades a sample pass or fail, each with a critique; the judge's prompt is revised until its grades agree. The graded sample becomes the judge's eval cases.
- [Choose from options](choose-from-options/card.md): On questions of taste — UI, naming, the shape of an API, the structure of a module — the agent makes 2–3 options. The person picks one and briefly explains why.
- [Diff review by a person](human-diff-review/card.md): The person comments on the PR; the agent fixes the comments and replies in the thread.
- [Discovery decision](discovery-decision/card.md): The agent answers an agreed question with prototypes, probes and spikes; the gate checks that each claim names evidence that exists and no spike code is in main, and a refuter tests each claim.
- [Escalation on uncertainty](escalation-on-uncertainty/card.md): The agent stops by itself and asks a question when it cannot choose between options or has found a contradiction in the requirements.
- [Interview](interview/card.md): Before writing code the agent asks the person about requirements, edge cases and trade-offs, and writes the answers into a spec in the repository.
- [Observe and interrupt](observe-and-interrupt/card.md): The person does not approve every step. They watch from the side and step in when they see the work going the wrong way.
- [Plan approval](plan-approval/card.md): The agent studies the code read-only and proposes a plan; a person edits and approves it, and the agent then works by the plan on its own.
- [Result demo](result-demo/card.md): The agent shows the working feature: a link to a preview environment, screenshots, a before/after video, recorded command output. The person judges the behaviour, not the code.
- [Stall detector](stall-detector/card.md): A hook hashes every tool call; the same call or cycle of calls five times in a row tells the agent to step back, and a second stall in the same task stops it for a person.
- [Steering: a repeated correction becomes a rule](correction-becomes-rule/card.md): Every correction a person makes is logged at the phase that should have caught it; the second of a kind is an escape, and it becomes a lint, a test or a line in CLAUDE.md.
- [Task restatement](task-restatement/card.md): The agent restates the task in its own words: what it understood, what is out of scope, and what will show it is done. A person answers "yes" or corrects the restatement.
- [Triage: every signal goes to one super-loop, with its oracle](triage/card.md): Triage merges each incoming error, alert, bot's PR, user's message or ticket with any open item on the same thing, and routes it to one super-loop; the route decides the oracle.
- [User feedback](user-feedback/card.md): One piece of user feedback becomes acceptance criteria tied to a reproducible scenario, approved by a person; the agent works to them, and they become its spec and test.
- [Users in production](production-users/card.md): A person reads the users' signal from production in aggregate: feedback, support tickets, A/B tests, dogfooding. It shows whether shipped work has value; a single item goes on to user-feedback.

### Testability

_Behaviour can be checked by tests, and the tests catch what they should._

- [A new check incubates before it blocks](check-incubation/card.md): A new test or eval runs many times on a schedule without blocking; it blocks pull requests only after a record of passes, and a blocking check that flakes goes back to quarantine.
- [A test must pay for its upkeep](test-admission/card.md): Before adding a test, the agent names the contract it protects, the regression that breaks it and why no existing test catches it, and shows it failing; a test without the three answers is not added.
- [Code coverage](code-coverage/card.md): The agent runs coverage and writes tests for the uncovered branches.
- [Mutation testing](mutation-testing/card.md): The agent sees surviving mutants — code changes the tests did not notice — and writes tests that catch them.
- [Run the tests first](run-tests-first/card.md): Before changing anything the agent runs the whole suite. It learns the state of the project and which tests already fail, so later it does not mistake them for its own regressions.
- [Steering loop](steering-loop/card.md): Every escape, a failure that got further than it should have, becomes a must-fire case at the phase that should have caught it, and the loop at that phase is fixed or added.
- [Unit tests, red/green TDD](red-green-tdd/card.md): The agent writes a test and sees it fail, then writes the code until the test passes, then refactors.

### Maintainability

_The code is easy to read, change and extend: modularity, analysability, modifiability, evolvability, understandability._

- [Architecture fitness functions](architecture-fitness-functions/card.md): The agent adds an import and runs `dependency-cruiser` or ArchUnit; a broken rule returns a message that names the rule and describes the layers, and the agent moves the code.
- [Auto-formatting hook](autoformat-hook/card.md): After every file write a hook formats the code, so the agent does not spend iterations fixing formatting by hand.
- [Code review by another agent](agent-code-review/card.md): The coding agent asks one or more reviewer agents, each with a fresh context, for a review, and fixes their comments until the reviewers are satisfied.
- [Coupling analysis](coupling-analysis/card.md): On a schedule a CLI reports fan-in, fan-out and cycles; what got worse than the baseline, minus intended hubs, becomes a maintenance item, and the refactoring must improve the numbers.
- [Doc linters for the knowledge base](knowledge-base-doc-lint/card.md): CI checks that the `docs/` folder is current, cross-linked and correctly structured. The agent reads the errors CI reports and fixes the docs.
- [Docs audit against the implementation](docs-audit/card.md): An agent with read-only tools checks one documentation page against the code and returns match, mismatch or inconclusive; a mismatch quotes the claim and cites the code.
- [Executable documentation](executable-docs/card.md): Doctests and a check of API responses against the OpenAPI schema turn a mismatch between the docs and the code into a failing test.
- [Garbage collection](garbage-collection/card.md): On a schedule, background agents find code that breaks the repository's "golden principles" and open small PRs to fix it. At OpenAI most took under a minute to review and merged automatically.
- [Linter with fix instructions](lint-with-fix-instructions/card.md): The agent runs the linter and reads each violation together with a "how to fix" text. Then it either fixes the violation or suppresses it with a justification.
- [Pre-commit / pre-push](pre-commit-pre-push/card.md): Fast checks, such as linting, run when the agent commits or pushes; a failing check blocks the commit or the push before the change reaches CI.
- [Review of document texts](document-review/card.md): The agent writes a brief, not the document. A separate writer writes the text from the brief. A fact check returns invented and missing facts; a reviewer returns error-pattern findings.
- [Simplification pass after the work](simplification-pass/card.md): When a piece of work is done, the agent simplifies it without changing behaviour; the checks stay green, tests are not weakened, and each significant removal waits for a person's approval.
- [Taste invariants: custom lints](taste-invariants/card.md): The agent breaks a team convention, such as an unstructured log line, a misnamed schema or a file over the size limit; a custom lint flags the violation in seconds and tells the agent how to fix it.

### Security

_Confidentiality, integrity, privacy, compliance, audit and licences._

- [A reviewer agent answers approval prompts](approval-reviewer-agent/card.md): A read-only reviewer model answers the agent's permission prompts in place of a person: it scores the action's risk and where its authorization came from, and a denial forbids a workaround.
- [Audit trail of agent actions](agent-audit-trail/card.md): The agent leaves evidence: commands with their output, screenshots, videos, commits. The reviewer checks the evidence instead of re-running everything.
- [Compliance hardening with mutants](compliance-mutants/card.md): An LLM takes one concern, such as data leaks, and writes mutants for it and tests that catch them; a mutation run shows the tests fail on the mutants and pass on the real code.
- [DAST](dast/card.md): OWASP ZAP scans the running preview from the outside: passively on every deploy, with attacks before a release. The agent fixes each alert the scan fails on.
- [Dependency analysis (SCA) and SBOM](dependency-scanning-sbom/card.md): The scanner reports a CVE in a dependency the agent added. The agent then picks a safe version.
- [Gates on risky actions](risky-action-gates/card.md): Before an irreversible action, the agent stops and asks a person to confirm it. In this card, a risky action means an irreversible one.
- [License check](license-check/card.md): The check fails on a forbidden license; the agent replaces the package.
- [SAST](sast/card.md): Semgrep or CodeQL reports a rule, a file and a line; the agent fixes the vulnerable pattern.
- [Secret scanning](secret-scanning/card.md): GitLeaks in pre-commit blocks a commit that contains a secret; the agent moves the secret into environment variables.
- [Security and data-handling review by an agent](security-review-agent/card.md): A subagent checks the code against a security checklist or rules such as "no user names should ever be sent to the web frontend", and returns findings with line numbers.

### Compatibility

_It works with other systems, versions, platforms and locales: integrability, interoperability, portability, i18n._

- [Breaking changes in the API](api-breaking-changes/card.md): The agent changes a schema; CI compares it with the schema on main and reports each break, and the agent restores compatibility or introduces a new API version.
- [Contract tests](contract-tests/card.md): The agent changes a provider and runs contract verification. Before a deploy, the agent runs `pact-broker can-i-deploy`. The command exits with code 0 ("yes") or 1 ("no").
- [Dependency updates](dependency-updates/card.md): Renovate or Dependabot opens a PR; the agent runs the sensors and fixes what broke. A script collects the age and activity of the dependencies, and an LLM writes recommendations.
- [i18n and pseudo-localization](i18n-pseudolocalization/card.md): A linter finds missing keys and hard-coded strings. E2E on a pseudo-locale shows truncated text.
- [Integration tests with emulators](integration-tests-emulators/card.md): The agent starts the real dependencies of the code (database, queue, cloud emulators), runs the tests against them and sees the errors in how the code works with those dependencies.
- [Lint and run database migrations](db-migration-lint/card.md): A migration linter points at a dangerous operation. The agent rewrites the migration, then applies it and rolls it back on a throwaway database.
- [Platform matrix](platform-matrix/card.md): CI runs the tests on several operating systems, runtimes and browsers. The agent sees which exact combination failed and fixes it.
- [Translations stamped with their source text](translation-sync/card.md): Each translation records a hash of the text it was translated from; a changed original makes it stale, and a check fails on broken params, link ids and code spans.

### Performance

_Time behaviour, resource use, capacity, scalability._

- [Benchmarks against a baseline](benchmarks-vs-baseline/card.md): The agent benchmarks its code against a baseline, such as existing libraries, and optimizes the code when its benchmark result is worse.
- [Bundle size budget](bundle-size-budget/card.md): size-limit "throws an error if the cost exceeds the limit". With `--why` the agent finds what bloated the bundle and removes it.
- [Lighthouse CI](lighthouse-ci/card.md): `lhci assert` fails when a preview page scores below an assertion's threshold, such as performance under 0.9. The agent reads the JSON report and `manifest.json`.
- [Load testing](load-testing/card.md): The agent runs k6, Gatling or Locust against a preview, sees p95 degrade and looks for the bottleneck in the traces.
- [Performance budgets through telemetry](perf-budgets-telemetry/card.md): The agent gets a performance budget, such as "service startup completes in under 800ms", queries the service's own traces and metrics, and optimizes the code until the service meets it.
- [Profiling](profiling/card.md): The agent takes a CPU or memory profile as text (the top N functions), makes a fix and compares the new profile with the original.

### Reliability

_Availability, fault tolerance, recoverability, resilience._

- [Chaos engineering](chaos-engineering/card.md): Experiments kill pods or zones in staging. From the alerts and SLOs, the agent finds the recovery mechanism that is missing.
- [Error tracking (Sentry)](error-tracking/card.md): Through Sentry MCP the agent gets the top errors, their stack traces and Seer's root-cause analysis; it reproduces one with a test, fixes it, and checks that the error rate fell after the release.
- [Fault injection (Toxiproxy)](fault-injection/card.md): A test makes a dependency slow, time out or go down through the Toxiproxy HTTP API; when the test fails, the agent fixes retries and error handling.
- [Fuzzing](fuzzing/card.md): The fuzzer finds an input that crashes the code. The agent turns the minimal crashing input into a regression test and fixes the code.
- [Health checks and smoke tests after deploy](health-checks-smoke/card.md): After a deploy, the agent polls `/health` and `/ready` and runs a smoke suite. On a red result, an investigator reads the startup logs and returns a Diagnosis.
- [Restore from backup and rollback](backup-restore-rollback/card.md): A job restores the database from a backup and rolls the release back. When the check fails, the agent fixes the procedure.
- [SLO degradation](slo-degradation/card.md): The agent watches the SLOs for latency, errors and availability. When an SLO degrades, the agent looks for the cause in logs, traces and recent deploys and proposes a fix.

### Observability

_What the system does can be seen and explained: logs, metrics, traces, debuggability, operability._

- [Browser console and DevTools](browser-console-devtools/card.md): The agent reads the page's console errors and network requests and fixes JS exceptions and 4xx/5xx responses.
- [Debugger and REPL](debugger-repl/card.md): The agent sets a breakpoint or opens a REPL and checks its hypothesis against real values instead of guessing.
- [Metrics (PromQL)](metrics-promql/card.md): The agent runs a scenario and compares error counters, latency and resource use with what it expects.
- [Structured logs and log queries](structured-logs/card.md): The agent starts the application, queries the logs, finds the error and fixes it (at OpenAI: LogQL against an ephemeral VictoriaLogs per worktree).
- [Tool-use telemetry from agent sessions](tool-use-telemetry/card.md): A script reads the agent's session transcripts and reports, per tool, model and file type, how often calls fail and why; the worst cases show what to fix in the tool or the guide.
- [Traces (OpenTelemetry)](traces-opentelemetry/card.md): The agent queries traces (TraceQL) and finds a slow or failed span.

### Deployability

_A change reaches where it runs, reproducibly and safely: builds, environments, rollouts, installability._

- [Canaries and feature flags](canary-feature-flags/card.md): When a canary release performs worse than the baseline, the release rolls back automatically and the agent gets the metrics of that release.
- [Changelog audit before a release](changelog-audit/card.md): Before a release, every commit since the last tag is matched to an entry in the changelog of the package it changed, and a check fails when a released section differs from its tag.
- [CI on clean infrastructure](ci-clean-infra/card.md): The agent pushes; autofixes apply themselves; the agent fixes the remaining failures locally.
- [Configuration check](config-validation/card.md): Two checks catch configuration errors: a validator checks the configuration against its schema; a smoke start runs with each configuration profile.
- [Isolated reproducible environment](isolated-environment/card.md): At the start of every task, the agent gets a clean environment: a devbox, a devcontainer, or a worktree with its own instance of the app, so the sensors give the same result for the same code.
- [Preview environments per PR](preview-environments/card.md): Every PR gets its own deployed environment. The agent runs e2e, DAST, Lighthouse and load tests against it and reads its logs.
- [Repository health agent](repo-health-agent/card.md): Scripts record the repository's flow metrics daily; an agent picks the worst trend, tests competing causes and proposes one change; a critic approves it before a draft PR.

### Usability

_People can use it: accessibility, UX, interaction._

- [Accessibility checks (axe, ARIA)](accessibility-checks/card.md): `@axe-core/playwright` finds WCAG violations and gives the selector for each one. `toMatchAriaSnapshot` catches structural problems that axe misses.
- [Agent navigation by the accessibility tree](accessibility-tree-navigation/card.md): The agent drives the page by Playwright MCP's accessibility snapshot instead of pixels; a button it cannot find by role and name means poor accessibility and a broken scenario.
- [AI judges on telemetry](ai-judges-telemetry/card.md): An AI judge is an LLM that checks a sample of responses and a sample of logs. It marks the anomalies it finds.
- [Layout continuity under CPU stress](visual-stability-oracle/card.md): A probe samples the layout of named regions on every frame while the CPU is slowed; declared invariants catch jumps, flashes, blank frames and overlaps that a final screenshot never shows.
- [UX evaluator with thresholds](ux-evaluator/card.md): A separate agent walks the app with Playwright MCP like a user, grades depth, functionality, design and code, and once calibrated fails a sprint below any threshold; the generator gets a breakdown.
- [Visual check with screenshots](visual-screenshot-check/card.md): The agent takes a screenshot, compares it with the mockup, lists the differences and fixes them.
